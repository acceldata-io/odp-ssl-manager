A repo can legitimately show zero audit events when nothing used it. Generate access (section 6) before calling it broken.

2. Audit configuration (per service ranger-<svc>-audit)

Every plugin must have real endpoints, not the stack placeholders (hdfs://hostname:8020, hdfs://localhost:8020, NONE):

xasecure.audit.is.enabled                          = true
xasecure.audit.destination.hdfs                    = true
xasecure.audit.destination.hdfs.dir                = hdfs://<nameservice>/ranger/audit      (HA: nameservice; non-HA: nn-host:8020)
xasecure.audit.destination.solr                    = true
xasecure.audit.destination.solr.zookeepers         = zk1:2181,zk2:2181,zk3:2181/infra-solr
xasecure.audit.destination.solr.force.use.inmemory.jaas.config = true      (Kerberos)
xasecure.audit.jaas.Client.option.serviceName      = solr                   (Kerberos: the SOLR service name, never the plugin's own)

On Kerberos clusters also keep the xasecure.audit.jaas.Client.option.principal/keyTab pair the Kerberos descriptor creates for the service.

Verification of the Ranger Admin truststore on RHEL: update-ca-trust does not extract a plain self-signed (non-CA) leaf certificate into the Java store. Import the certificate directly with keytool -importcert -cacerts .... A later update-ca-trust run replaces that file, so import the CA that signed the service certificate when you can instead of leaf certificates.

5. NiFi and NiFi Registry (need TLS first)

NiFi 2 and NiFi Registry 2 load their Ranger authorizer only when the web server is secured. With nifi.web.https.port (or nifi.registry.web.https.port) empty the policy cache stays a 0-byte file, no plugin registers and no audit is written. What was done on this cluster, in order:

1. Generate a CA and per-host keystores with the SSL manager, and update only the two UIs' Ambari configs. Run on the Ambari host as root, from the cloned repo with a conf/ca.properties listing every cluster host: python3 bin/ssl_manager.py --ca --properties=conf/ca.properties --isOverwrite --enable-ssl --ui=NIFI2,NIFI_REGISTRY2 --host <ambari> --cluster <name> --protocol=http --port=8080 Without --scpKeyFile the tool skips copying the certificates (it needs root ssh to every host, which is disabled here). 2. Copy keystore.jks and truststore.jks of each host to /etc/security/certificates on that host (directory 755, files 644). Ranger Admin's host needs them too: its keystore identity is the client NiFi authorises. 3. Restart NiFi 2 and NiFi Registry 2. They now listen on https (9191 and 62443 here). 4. Run bin/post_ssl_steps.py --steps ranger-repos,nifi-ranger from a machine that can resolve the cluster host names. ranger-repos moves the repos to https with SSL authentication and the client keystore, and nifi-ranger creates Ranger users for the certificate identity of Ranger Admin and every node, plus the /resources or /policies READ and /proxy WRITE policies. The order matters: nifi-ranger only acts on repos that already use https. 5. Set the audit destinations (section 2) on ranger-nifi2-audit and ranger-nifi-registry2-audit: HDFS and Solr true, real directory and ZooKeeper quorum. Restart. 6. Solr audit from NiFi needs SolrJ 8.11.3. The NiFi Ranger bundle ships SolrJ 9.7 with Jetty 12 and fails with NoClassDefFoundError: org/eclipse/jetty/client/util/SPNEGOAuthentication. Until the fixed NAR is built (NiFi branch ODP-8280), replace the SolrJ 9 and Jetty 12 jars in nifi-ranger-nar-*.nar (NAR-INF/bundled-dependencies) and in nifi-registry2/ext/ranger/lib with solr-solrj-8.11.3.jar and the Jetty 9.4 http/io/util jars, clear the unpacked NAR work directory and restart. Keep the originals.

Result: Test Connection passes, 2 NiFi plugins and 1 Registry plugin on the latest policy version, audit events in Solr and HDFS.

Note: the SSL manager itself failed on Python 3.12 (RawConfigParser.readfp was removed). That is fixed on the ODP-8311 branch.

6. Knox: put the plugin in the request path

The Knox plugin only runs if the topology authorizes through Ranger. Check the topology content in Ambari (topology config):

<provider><role>authorization</role><name>XASecurePDPKnox</name><enabled>true</enabled></provider>

AclsAuthz means Ranger is bypassed: the plugin does not register and nothing is audited. The Knox service advisor makes this switch when the plugin is enabled from the UI; clusters built from a blueprint can keep AclsAuthz. Change it and restart Knox.

8. Checking everything at once

A small script used during this work lists, per repo: Test Connection result, the newest Solr audit event, the newest HDFS audit file and how many plugins are on the latest policy version. The data sources are the Ranger public API (/service/public/v2/api/service, /service/plugins/services/validateConfig, /service/assets/accessAudit, /service/plugins/plugins/info) and hdfs dfs -ls -R /ranger/audit.

9. Known gaps on this cluster

  • KMS: HDFS audit works; its Solr events are not shown in the admin audit view.
  • HBase: one of five plugins (the hbaseMaster on the first host) stays on an older policy version. It is probably a standby master that has not started its plugin; not confirmed.
  • The Trino and Knox certificate imports, the Knox demo LDAP start, the Ranger Admin truststore change and the SolrJ replacement in the NiFi NAR are manual on this cluster. They are not in the mpack or blueprints, so a rebuilt cluster needs them again.
